Diagnostics (read-only)

Realistic thresholds from the manuscript: a primary fit capturing 60–70% of the macroscopic holding plateaus is a good fit; for secondary streams, under 30% of inflections in the temporal neighbourhood and under 5% near-exact is normal. No pass/fail at 95%.

X loss — how badly the timing fits. It is 0.5 × (1 − change-point match) + 0.5 × (1 − plateau capture). 0 is a perfect timing fit, 1 is no timing fit at all. Lower is better.

Change-points % — the share of the jumps in the user's data that have an FPS-R jump within ± the X threshold (frames). This is the timing alignment the eye sees on the plot.

Plateaus % — the share of the holding plateaus in the user's data whose duration FPS-R captures. Together with change-points % it makes up the X loss.

Mean hold, user vs FPS-R — the average hold duration in frames for each curve. If FPS-R's holds run much longer or shorter than the user's, no amount of scrubbing will fix the timing — the engine's hold parameters (min/max hold, periods) need to change.

Hold-histogram overlap % — how much the two hold-duration distributions overlap. 100% means the two curves hold for the same lengths of time with the same frequencies, even if the individual jumps land on different frames.

Y loss — how badly the values fit. It is the weighted root-mean-square error between the user's values and FPS-R's values, after FPS-R has been stretched and shifted by the fitted stretch below, normalised by the user's value range and capped at 1. 0 is a perfect value fit. Lower is better.

RMSE (% of range) — the same value error in the user's own units, and as a percentage of the user's value range, so the error can be judged big or small for the dataset.

Correlation — the Pearson correlation between the two curves, from −1 to 1. 1 means the shapes move together exactly; 0 means no linear relationship; negative means they move in opposite directions. A high correlation with a poor Y loss usually means the fitted stretch is doing the work.

Fitted stretch ×a + b — the least-squares scale (a) and offset (b) applied to FPS-R's 0–1 values to best match the user's values. This is the transform the Y loss is measured through. If a is near 0, FPS-R's shape barely matters to the score — the fit is being carried by the offset alone.

Combined loss — wX × X loss + wY × Y loss, using the loss weights from the Validator panel. This is the single number the fit is ranked by.

Normalised loss — the combined loss divided by (wX + wY), so it always sits between 0 and 1 no matter what weights are set. This is what drives the FPS-R curve's colour.

Curve colour — the FPS-R curve is coloured by the normalised loss on a green → amber → red ramp: green near 0 (good fit), red near 1 (poor fit). The colour and the numbers always agree, because both come from the same score.
